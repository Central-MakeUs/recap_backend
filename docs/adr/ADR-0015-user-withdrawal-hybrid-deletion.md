| 항목 | 값 |
| --- | --- |
| 상태 | Accepted |

## 맥락 (Context)

Apple App Store 심사 가이드라인 5.1.1(v)가 "계정 생성을 지원하는 앱은
인앱 계정 삭제도 지원해야 한다"고 요구하는 것으로 알려져 있어(정확한
최신 문구는 별도 재확인 필요, 아래 후속 참고), 이번 심사 제출 전
회원탈퇴 기능이 필요해졌다.

탈퇴 시 무엇을 어떻게 지울지 결정하며 세 가지 서로 다른 요구가
충돌했다: (1) 원본 이미지·정보카드가 유저당 데이터의 대부분을
차지하므로 이 부분은 반드시 지워 공간을 확보해야 한다, (2) 추후
결제 기능이 유저를 참조할 안정적인 식별자가 필요하다, (3) 누적
가입자 수 같은 운영 지표를 추후 집계할 수 있으면 좋다.

## 결정 (Decision)

**하이브리드 삭제**를 채택한다.

```
InfoCard + S3 원본 이미지  → 하드 삭제 (완전히 제거)
RefreshToken              → 전체 즉시 폐기(삭제)
User row                  → 삭제하지 않고 유지, 다만:
  - deviceId를 복구 불가능한 랜덤 값으로 덮어씀(컬럼이 NOT NULL
    UNIQUE라 null 불가)
  - oauthProvider, oauthId, email, fcmToken을 null로 초기화
  - withdrawn 플래그를 true로 설정
  - createdAt(가입 시점)은 그대로 유지 — 지표 집계용
```

Access Token(JWT)은 무상태 인증 특성상 서버가 즉시 강제 만료시킬
방법이 없다. 탈퇴 직후 최대 30분(Access Token 만료 시간) 동안
기존 토큰이 기술적으로 유효할 수 있는 리스크를 낮은 심각도로 감수한다
— RefreshToken은 즉시 폐기되므로 재발급은 불가능하고, 자연 만료로
resolved된다.

## 고려한 대안 (Considered Options)

1. **완전 하드 삭제(User row까지 제거) (기각)** — 추후 결제 기능이
   User를 참조하는 FK가 깨지거나 우회 로직이 필요해짐. 누적 가입자
   수 같은 집계 지표도 함께 사라짐.
2. **완전 소프트 삭제(전부 유지, 플래그만) (기각)** — 유저당 데이터의
   대부분을 차지하는 이미지·정보카드가 그대로 남아 공간 확보라는
   원래 목적을 달성 못 함. deviceId/oauthId 같은 식별 정보가 그대로
   남아있으면 "실제로 삭제됐다"고 보기 어려움 — Apple 가이드라인의
   취지와도 부합하지 않을 수 있음.
3. **하이브리드 (채택)** — 공간을 실제로 잡아먹는 데이터는 하드
   삭제, 결제/지표에 필요한 최소 뼈대(User row)만 개인 식별 정보를
   제거한 채 보존.

## 결과 (Consequences)

### 긍정
- 이미지·정보카드가 실제로 삭제되어 스토리지 공간이 확보됨.
- 추후 결제 기능이 User row를 안전하게 참조 가능.
- 누적 가입자 수, 탈퇴율 같은 집계 지표를 개인 식별 없이 계산 가능
  (SELECT COUNT(*) 수준, 특정 개인의 탈퇴 시점을 추적하는 건 불가능).
- 재가입 시 익명화된 옛 row와 자연스럽게 단절되어(oauthId가 사라져
  옛 row를 찾을 방법이 없음), 별도의 재가입 유예/차단 로직이 필요
  없음 — 그냥 새 User가 생성됨.

### 부정 / 트레이드오프
- Access Token이 탈퇴 후에도 최대 30분간 유효할 수 있는 낮은 심각도
  리스크를 감수함.
- User row 자체는 영구히 남으므로, "완전한 데이터 소거"를 요구하는
  더 엄격한 개인정보 규정이 적용될 경우 재검토 필요할 수 있음(지금은
  Apple 심사 요건 충족이 목적).

## 후속 / 미결정

- [ ] Apple App Store Review Guidelines 5.1.1(v) 정확한 최신 문구
      재확인 필요(검색 도구 이슈로 이번엔 직접 검증 못함)
- [ ] 더 엄격한 개인정보 규정(예: GDPR류) 적용 시 User row까지 완전
      삭제가 필요해질 수 있음 — 그 시점에 재검토
